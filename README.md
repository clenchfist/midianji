# 密电机

本机运行的信息加密工具，支持随机密码本、密文翻译及手机离线网页

原版网址：https://clenchfist.github.io/midianji/

密电机 Lite：https://clenchfist.github.io/midianji/lite/

Lite 原名密电机2号，面向娱乐和短消息，新版使用精简的汉字密文，密码本文件格式及浏览器记住密码本的方式不变

汉字格式 v6 只更换密文的显示编码，加密后的二进制数据与 v5 相同，保留 AES-128-CTR、HKDF-SHA-256 派生的独立加密和认证密钥、32位 HMAC-SHA-256 认证标签、48位随机启动号及16位辅助密码本检查值，每次加密仍使用新随机参数，不显示固定密码本编号

原文仍从 UTF-8、UTF-16 和21位字码中选取较短方式，并尝试内置的 DEFLATE 压缩，只有压缩后更短才采用；新的显示编码用每个汉字承载14位数据，末尾一个汉字记录字节长度余数，开头仍随随机参数变化，复制时请保留完整内容

相对于上版 v5 数字密文，实测“你好”从45位数字变成11个汉字，“今晚八点老地方见”从75位变成18个汉字，一条40字普通消息从230位变成55个汉字，显示字符数减少约76%；检查覆盖整个合法包长度范围，汉字密文字符数均不超过对应 v5 数字密文的一半

这里的缩短按显示字符数计算，不代表文件字节数也减少76%；例如“你好”的密文从45字节变为33字节，汉字密文每个字符在 UTF-8 中占3字节，原有加密参数和校验强度没有继续降低

48位随机启动号明显降低了长期大量使用时的碰撞余量，32位认证标签也明显低于旧版128位标签；独立随机猜中一个认证标签的概率约为1/2^32，多次尝试会累积风险，辅助检查值不能替代认证；本格式按娱乐用途取舍，未经过独立安全审计，不用于敏感通信或长期海量消息

压缩会透露更多有关内容重复程度的长度信息，没有长度填充，也没有前向保密能力；纯数字本身只是编码形式，程序公开并不隐藏算法

Lite 保留 v1–v5 解密能力，兼容旧版2号和旧 Lite 的数字密文，可继续使用旧密码本；发送新密文前，收发双方都须联网刷新 Lite 或换用新版 HTML，旧程序无法还原 v6 汉字密文

收发双方均使用最新版 Lite，Lite 也可以还原原版密文

两版的离线缓存分开

内置压缩组件为 [fflate 0.8.2](https://github.com/101arrowz/fflate/tree/v0.8.2)，采用 MIT 许可，完整许可包含在 HTML 源码及 `THIRD_PARTY_NOTICES.txt` 中；程序使用同步压缩功能，不调用外部服务、不上传正文，也不要求手机浏览器提供 CompressionStream

## Lite 便利模式

Lite 同步原版的低饱和配色、紧凑布局、宋体、文本框行距与少量内边距，保留生成、导入、导出和重命名功能

Lite 将生成或导入的密码本记在当前浏览器，下次打开从下拉列表选择即可，无需重复导入；浏览器清理站点数据、无痕模式或更换设备可能导致记录丢失，重要密码本应导出文件备份

继续使用原2号的存储键及记录格式，使用同一浏览器访问新网址时，原有记录仍可选择使用；不会自动选择或匹配密文所用密码本

下拉列表中的红色“删除”会删除当前浏览器记住的对应密码本，不删除已导出的文件

旧 `/2/` 地址已停用为提示页，不再提供加密程序；提示页及旧服务工作线程更新会清理该旧地址的程序缓存并注销其离线服务，不清除密码本记录，也不影响原版或 Lite 的离线缓存

已经下载的 HTML 或尚未联网更新的旧离线副本无法远程撤销，重新联网打开旧地址后才会接收停用更新

## 原版密码本保存方式

原版与 EXE 同步使用紧凑界面、宋体、适中的上下行距与内边距，文本框使用浏览器原生滚动，不在滚动时反复重绘

原版不再把生成或导入的密码本写入 localStorage、IndexedDB 或其他浏览器数据库，也不把文件句柄持久化

支持直接选择文件位置的浏览器（例如 Mac、Windows 上的 Chrome／Edge）先选择保存位置，再生成并写入该文件，重新读取核对成功后自动导入本次会话，取消选择不会生成密码本

支持系统文件分享但不支持直接保存接口的手机／平板浏览器，可先在内存中准备密码本，再由用户点击“选择保存位置”，在系统菜单中选择“存储到文件”／“保存到文件”及本机文件夹，返回页面后选择刚保存的文件核对，只有文件内容与新密码本匹配时才启用

系统菜单不是网页自己的文件保存框，网页不能限制分享目标、获知最终路径或保证系统不保留临时文件，也不能检查文件夹是否会同步到云端；系统菜单返回成功不视为保存成功，用户必须选回文件核对，iPhone／iPad 应选择“我的 iPhone／iPad”，如果系统没有文件保存入口，请取消

系统不支持分享 `.itbook` 文件时会使用 `.itbook.txt` 文件，内容、校验和密钥均不改变，两种扩展名都可直接导入，未核对的密码本不加入当前列表，取消或离开页面会丢弃临时内容，程序不写浏览器数据库，也不自动下载副本

仅提供文件夹选择接口的浏览器可以在准备后直接选择文件夹保存，写入后自动重读核对，已有同名文件时拒绝覆盖

对于小米等未开放文件分享／直接保存接口的环境，生成入口不再因缺少这些接口而拒绝打开，准备后可使用“兼容下载方式”：用户先在浏览器中确认本机下载目录，再主动勾选同意按浏览器设置保存，点击“按下载目录保存”才发起一次本机 Blob 下载，下载请求不代表保存成功，必须选回匹配文件核对后才启用

兼容下载由浏览器决定目录、是否弹框及文件名，网页不能选择或核实目录、强制每次弹框、获知下载完成或保证浏览器／系统不保留临时文件，不能接受此限制时应取消；单次准备只允许一次下载请求，取消、页面关闭或核对完成会撤销临时 Blob URL，不向服务器上传密码本

导入的密码本只在本次页面的内存中使用，关闭或刷新页面后须重新导入，不会自动匹配密文所用密码本

重命名将名称写回导入的原文件，不另存副本，也不改变密钥，文件本身的文件名不自动改变

下拉列表中的红色“删除”仅移除本次会话的记录，不删除原位置的密码本文件

重命名仍须能够写回原密码本文件，不提供另存副本的替代方式，Mac Safari 若系统菜单没有文件保存入口，可使用 Mac Chrome／Edge 直接保存，是否使用兼容下载须由用户明确确认

旧版浏览器记录不会自动导入使用，也不会直接删除，检测到旧记录后须逐本另存并核对，再由用户清除；仅点击下载不足以通过核对，使用下载方式保存后须重新选择文件核对

上述严格保存方式针对原版，Lite 维持既有的浏览器记住密码本行为

## 自动发布

仓库的 `main` 分支提交更新后，GitHub Actions 会自动构建、检查并部署到 GitHub Pages

首次启用时，在仓库的 Settings → Pages → Build and deployment → Source 中选择 GitHub Actions

## 修改页面

编辑 `source.html` 并提交到 `main`，构建会自动更新脚本校验值和离线缓存版本，不需要手动修改长校验字符串

Lite 独立源码为 `source2.html`，同一次构建会发布到 `dist/lite/`，`dist/2/` 仅保留停用提示及旧离线缓存清理逻辑

联网时获取新的页面，断网时使用已经缓存的程序

## 本地预览

安装 Node.js 22 或更新版本，然后运行

```sh
npm run build
npm test
npm run dev
```

预览地址为 `http://127.0.0.1:5175/midianji/`

## 手机

用 Safari 打开发布后的 HTTPS 地址，添加到主屏幕，再从主屏幕打开并导入密码本

第一次从主屏幕打开时保持联网，等底部显示“可离线使用”后可断网使用

## 文件范围

发布内容只有 `dist` 中的程序、图标及离线缓存逻辑，不包含密码本或消息

不要把 `.itbook` 密码本、私人消息或登录凭据提交到此仓库

原版密码本仅由用户明确保存至所选文件位置，程序和离线缓存不上传或备份密码本、原文和密文

页面运行期间仍需在内存中使用密码本，浏览器、操作系统、备份软件及云同步文件夹自身的行为不受网页控制，所选文件夹是否同步到云端取决于设备设置
